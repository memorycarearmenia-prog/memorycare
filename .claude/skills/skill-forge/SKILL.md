# Кузнец

Скилл, который кует другие скиллы. Финал системы и его инфраструктура: закрывает разрыв между «я об этом думаю» и «у меня это есть». Два режима:

- **Сборка** — собрать готовый скилл из текущего диалога или описания.
- **Поиск** — просканировать историю чатов и предложить, что упаковать в скилл следующим.

## Когда запускать

- Рабочий процесс только что сработал в чате и должен стать повторяемым
- Нужно отредактировать существующий скилл
- Аудит: после плотной работы с Claude накопились паттерны — найти самые ценные
- Ловишь себя на том, что просишь Claude одно и то же по третьему разу

## Режимы

**Сборка** → из текущего диалога (извлечь то, что только что сделали) или из описания (автор описывает — ты собираешь). На выходе — полный SKILL.md + путь установки + тестовый запрос.
**Поиск** → скан истории чатов (если доступны инструменты истории), кластеризация повторов 3+ раз, ранжирование по рычагу, кандидаты со свидетельствами и ROI.

## Входные данные

Сборка (опционально): существующие скиллы для разведения триггеров, эталонный SKILL.md для совпадения стиля.
Поиск (опционально): окно времени (по умолчанию 90 дней), фильтр по домену (напр. только контент), минимальная частота (по умолчанию 3).

## Анатомия SKILL.md

```
---
name: имя-через-дефис
description: [Абзац под триггеринг с 5+ триггер-фразами]
---

# Человекочитаемое имя
## Когда запускать
## Входные данные
## Структура вывода
## Процесс
## Критические правила
```

## Структура вывода

### Режим «Сборка»
Готовый SKILL.md как код-блок + сохранённый файл + путь установки + тестовый запрос.

### Режим «Поиск»
```
# Возможности для скиллов — [дата]

## Просканировано: [окно, сколько чатов, найдено паттернов]

### 1. [Название паттерна]
**Что повторяешь:** [задача]
**Частота:** [X раз за Y дней]
**Примеры чатов:** [конкретные как свидетельство]
**Почему это скилл:** [обоснование]
**Имя + триггеры:** [предложение]
**ROI:** [время за раз × частота]
### 2. …

## НЕ должно быть скиллами: [паттерны, которым лучше остаться разовыми, и почему]
## Собрать первым: [топ-выбор]
```

## Принципы триггер-описания

Описание — единственное, что видит Claude, решая, запускать ли скилл. Оно должно: (1) открываться тем, что делает скилл; (2) перечислять 5+ триггер-фраз явно; (3) называть контексты применения; (4) быть слегка напористым — велеть запускаться даже без точного имени.

## Процесс

1. **Сборка:** определи источник (диалог или описание) → из диалога сначала суммируй паттерн и подтверди → имя через дефис → описание по принципам → тело (когда запускать, входные, вывод, процесс, правила) → отдай SKILL.md код-блоком И сохрани файл → путь установки → тестовый запрос.
2. **Поиск:** подними окно истории → найди повторы по ключевым словам → кластеризуй → ранжируй по частоте × рычаг → к каждому имя, свидетельства, ROI → пометь 2–3, что НЕ должны быть скиллами → назови топ → передай в режим «Сборка».

## Критические правила

- Подтверждай рабочий процесс перед сборкой — никогда не выдумывай намерение.
- Описание ОБЯЗАНО перечислять 5+ триггер-фраз.
- Раздел «Критические правила» — обязателен в каждом собранном скилле.
- Имя — через дефис, без пробелов, подчёркиваний и заглавных.
- Помечай пересечения с существующими скиллами — предложи слить, заменить или развести.
- Отдавай и код-блоком, И сохраняй файл. Всегда предлагай тестовый запрос.
- **Поиск:** 3+ повторения, чтобы квалифицироваться (два — совпадение). Цитируй КОНКРЕТНЫЕ чаты. Всегда включай «не должно быть скиллами» — раздувание набора реально. Ранжируй по рычагу, не по частоте. Заканчивай передачей в «Сборку».
- Не хватает ключевого входа (подтверждённый рабочий процесс (режим «Сборка»)) — задай ОДИН уточняющий вопрос и дождись ответа. Не генери вслепую.
- Брендбука нет — задай 1–2 вопроса (тон, обращение на «ты»/«вы») или пиши нейтрально и пометь: «голос не откалиброван».
- Режим «Поиск» без инструментов истории чатов: попроси автора вставить 3–5 последних диалогов или перечислить, что он просит чаще всего, — и работай по этому материалу.
- Всегда заканчивай вывод строкой «→ Дальше: установи собранный скилл и прогони тестовый запрос» — автор должен видеть следующий шаг конвейера.

## Связка с системой

Кузнец стоит в финале и замыкает систему: режим «Поиск» находит, чего не хватает системе, режим «Сборка» это докручивает. Для автора это апселл — после того как он освоил 10 готовых звеньев, он этим скиллом кует свои, под себя.

## Как на этом заработать

Сборка скиллов на заказ — премиальная услуга: упаковываешь чужой рабочий процесс в готовый скилл за деньги. Для эксперта это способ продать свою методологию как продукт (скилл-пак), а не только как услугу.
